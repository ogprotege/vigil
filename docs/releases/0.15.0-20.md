## Release scope

Build 20 removes every App Group file lock from the app's launch path. Build
19 was killed on a TestFlight device with RUNNINGBOARD `0xdead10cc` 1.3
seconds into a never-foregrounded launch: `AppModel` construction ran inside
`App.main()` before UIApplicationMain and held the per-account snapshot flock
while JSON-decoding when the system suspended the process. No background-task
assertion can exist that early, so the guard approach from build 18 could not
cover this path.

The launch initializer now performs no App Group locking. The initial disk
load moved to the idempotent `AppModel.ensureLoadedFromDisk()`, which runs
under `SuspensionGuard` from scene activation, the root scene task, and the
`BGAppRefreshTask` handler. Presentation shows a launch frame until the load
completes. Identity mutations and refresh-all load persisted state before
acting so an index write from an unloaded model cannot erase accounts already
on disk. `SnapshotStore` holds its per-account flock only for the raw byte
copy and rotation — encoding before the lock, read-path decoding after
release — in both the app and widget processes.

The fix landed through [PR #38](https://github.com/ogprotege/vigil/pull/38),
merged as `34f3bc3`.
