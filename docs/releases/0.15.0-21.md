## Release scope

Build 21 carries four user-facing repairs merged through PRs #41–#45.

Account removal previously did nothing: the confirmation dialog's action read
its pending account from state that dialog dismissal had already cleared, so
confirming silently removed nothing. Both Accounts-screen dialogs now receive
the account through the dialog's `presenting:` data, demo mode removes
accounts in memory only, and UI tests walk the removal confirmation and the
history-recovery dialog end to end.

Re-linking recovered its missing path: a provider response this build cannot
read (**Provider changed**) previously dead-ended account linking in an
OK-only alert, so removing a drifted account made it impossible to re-add.
That failure now offers **Save anyway**, while rejected credentials still
fail hard.

Degraded freshness became honest on every surface: retained readings age the
data ("Provider changed, data from 1 day ago") instead of claiming a check
time, in the visible line and in the Home card's spoken VoiceOver summary,
which previously replaced the corrected text with the old wording.

Kimi K3 accounts stranded since 2026-07-28 recover: the endpoint's
protobuf-style JSON omits zero-valued numbers, so a zero-usage session
arrived without its `used` field and the strict contract rejected the
response. A sanitized production capture proves the shape, and the
`zeroOmittedNumbers` contract flag accepts an omitted amount as exactly zero
only when the declared limit and the other amount agree. The provider-change
user guide and GitHub issue templates from PR #42 ship alongside.
